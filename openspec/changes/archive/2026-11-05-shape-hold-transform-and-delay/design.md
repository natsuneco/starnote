# Design: 図形スナップの長押し判定時間の延長およびホールド中ドラッグ変形

## Context

現在の図形自動整形（`recognizeShape`）および輪郭ホールド選択は、400ms/350ms という短いタイマーで発火していたため、通常の筆記中のわずかな静止でも誤判定が発生していました。
また、図形認識後にペン先を離さずにドラッグしても、一度計算された図形が固定され、サイズや角度の微調整ができませんでした。
詳細は [proposal.md](./proposal.md) を参照してください。

## Goals / Non-Goals

**Goals:**
- 長押し判定時間を 1000ms（1秒）に延長し、通常筆記時の誤スナップを完全に防止する。
- 図形スナップ後、ペンを離さずにドラッグした際、図形種別（直線、円、長方形）に応じた直感的な幾何変形（長さ・角度・サイズ伸縮）をリアルタイムに実行する。
- ペン離脱時にドラッグ変形後の最新座標でストロークを確定保存する。

**Non-Goals:**
- 確定済みストロークを後から選択して変形するバウンディングボックスハンドラー操作（なげなわ移動とは別機能）は今回スコープ外とし、描画直後のペンホールド時ドラッグに特化する。

## Decisions

### 1. 終点静止時間のみを計測するホールド判定アーキテクチャ
- **決定**: 描画中のポインタ移動中はタイマーを常時破棄（キャンセル）し、ペン先の移動が手ブレ許容値（6px）以内に収まり「完全に静止した状態」になってから初めて 750ms のカウントダウンを開始する。
- **理由**:
  - 従来のロジックでは描画中の移動時間もタイマーに加算されていたため、ゆっくり書いた文字や長いストロークの終盤で早すぎる誤爆が発生していた。
  - 移動中のタイマー破棄を徹底することで、どれだけ長く時間をかけて書いたストロークであっても、書いている途中で図形認識が発火することは構造的に不可能となる。
  - 静止判定時間 750ms は、意図してホールドした際にはストレスなく素早く発火し、通常筆記時の小休止では発火しない絶妙な快適時間を実現する。

### 2. スナップ後ドラッグ変形エンジン
`snappedShapeRef` がセットされた後、ペン先が移動した際の変形計算を `src/lib/gesture/shapes.ts` にヘルパー関数 `transformSnappedShape(shape, currentPoint, initialData)` として集約。

1. **直線 (`type: 'line'`)**:
   - 始点 $P_{start}$（`shape.points[0]`）を固定アンカーとする。
   - 終点 $P_{end}$ を現在のペン先座標 `currentPoint` とする。
   - 始点〜終点を直線補間した点列を再生成。
2. **円 (`type: 'circle'`)**:
   - 初期スナップ時の中心点 $(cx, cy)$ を保持。
   - ペン先座標 `currentPoint` と中心点のユークリッド距離を新半径 $R = \sqrt{(x - cx)^2 + (y - cy)^2}$ とする。
   - 中心 $(cx, cy)$、半径 $R$ の円周点列（64分割）を再生成。
3. **長方形 (`type: 'rectangle'`)**:
   - スナップ発生時のペン先から最も遠い対角の頂点 $P_{anchor}$ を固定アンカーとする。
   - $P_{anchor}$ と `currentPoint` を両端とする矩形領域を算出し、4頂点を結ぶ閉ループ点列を再生成。

### 3. レンダリング同期
- ドラッグ移動イベント（`handleNativePointerMove`）内で、変形された最新の `ShapeRecognitionResult` を `renderSnappedShapePreview` に渡してオーバーレイ Canvas にリアルタイム再描画。
- ペン離脱（`commitActiveStroke`）で変形後のストロークを確定。

## Risks / Trade-offs

- [長押し時間の延長によるユーザーの体感遅延] → 700ms は標準的なメモアプリの標準値であり、意図して図形を描く際にはちょうど良く、通常文字の筆記誤爆を防ぐメリットが遥かに勝る。
