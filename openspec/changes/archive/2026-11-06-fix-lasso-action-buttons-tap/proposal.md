# Proposal: なげなわ選択アクションボタン（削除・解除）のペンタップ操作バグの修正 (Fix Lasso Action Buttons Pen Tap)

## 1. 課題と背景
StarNote では、なげなわツールまたは閉ループの輪郭ホールドによって手書きストロークを選択すると、青い破線のバウンディングボックスと共に、上部にアクションバー（「削除」ボタンおよび「✕（選択解除）」ボタン）が表示されます。

しかし現在、このアクションボタンを Apple Pencil などのスタイラスペン（またはタッチ）でタップした際、以下の不具合が発生しています：
1. **ボタンが反応しない**: 「削除」や「✕」ボタンを押しても削除や解除のハンドラーが実行されない。
2. **選択が即座に解除される**: ボタンをタップした瞬間に選択枠が消滅してしまう。
3. **誤ったインクが描画される**: ボタンをタップした位置に、ペンのインク（ドットや短い線）が意図せず描画されてしまう。

### 根本原因
- `DrawingCanvas` の用紙コンテナ全体にネイティブな `pointerdown` リスナー（`handleNativePointerDown`）が登録されている。
- アクションバー内のボタンをペンでタップすると、`pointerdown` イベントが用紙コンテナへバブリングする。
- `handleNativePointerDown` はイベントの発生元（`e.target`）が UI 要素（ボタンやアクションバー）であるかをチェックしておらず、キャンバス面がタップされたと誤認する。
- ボタン位置はストロークの選択範囲外（`-top-10` の外側）であるため、`isPointInSelection` が `false` となり、`setSelectedStrokeIds([])` が即座に発火して選択が解除（ボタンが DOM から消滅）される。
- 同時に `e.preventDefault()` と `container.setPointerCapture()` が呼ばれるため、ブラウザ標準の `click` イベントが握りつぶされ、さらにペン描画セッションが開始されてその位置にインクが描画されてしまう。

## 2. 解決アプローチ
1. **UI 領域でのイベント早期離脱**:
   - `handleNativePointerDown`、`handleNativePointerMove`、`handleNativePointerEnd` の先頭で、`e.target` がアクションバー要素（`[data-lasso-actions]` または `button`）であるか判定。
   - アクションバー内の操作である場合は、キャンバス描画の開始、`e.preventDefault()`、`setPointerCapture()`、および選択解除処理を一切行わずに直ちに `return` する。
2. **イベントバブリングの確実な遮断**:
   - アクションバーコンテナおよびボタンに `onPointerDown={(e) => e.stopPropagation()}` および `onPointerUp={(e) => e.stopPropagation()}` を明示的に指定し、ポインターイベントの親伝播を遮断する。
3. **ペン先・タッチ双方でのクリック確実性向上**:
   - ボタンクリックハンドラーが iOS Safari / PWA 環境においてスタイラスペンのタップで確実にトリガーされるようにする。

## 3. 期待される効果
- なげなわ選択後に、Apple Pencil のペン先で「削除」ボタンをタップすると、選択中のストロークが一発で確実に削除される。
- 「✕」ボタンをタップすると、インクを描画することなく選択枠のみが解除される。
- UI ボタンをペンでタップした際に、用紙上に不要なドットやストロークが描画されることが一切なくなる。
