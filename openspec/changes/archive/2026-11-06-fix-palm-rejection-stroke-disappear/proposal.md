# Proposal: パームリジェクション漏れによるストローク誤消去（誤Undo）の修正 (Fix Palm Rejection Stroke Disappear)

## 1. 課題と背景
iPad Safari（PWAスタンドアロン動作含む）において、Apple Pencil で手書きノートを描いている最中、**「書いた直後にストロークが勝手に消えてしまう」** という現象が散発的に発生していました。

### 根本原因
原因調査の結果、以下の3つの問題が重なり、**筆記中またはペン先を離した直後の手のひら（パーム）の接触が「2本指タップによる取り消し（Undo）」として誤判定されていたこと**が特定されました：

1. **`touchcancel` の誤判定**:
   iPadOS がパームを検知した際にブラウザへ送るキャンセルイベント `touchcancel` が、通常の指離脱処理 `handleTouchEnd` にそのままバインドされていた。このため、OSがパームとしてキャンセルした接触が、StarNote 側で「短時間の2本指タップが完了した」と解釈されて `onUndo()` を発火させていた。
2. **ペン直近活動タイムスタンプ（クールダウン）の欠如**:
   ペンを画面から離した瞬間（`pointerup`）にペンのアクティブ状態が即座に `null` にクリアされるため、ペン先を離した直後（10〜200ms）に手のひらを浮かせた際、ペンの保護ガードをすり抜けて 2本指タップ判定が成立していた。
3. **ペン描画時のマルチタッチ状態の残存**:
   手のひらが画面に触れた状態（2点接触）でペン先が画面に触れて線を描いた際、マルチタッチ状態がクリアされずに生き残っていたため、ペンで描き終えた後に手が離れると Undo が発火していた。

## 2. 解決アプローチ
本改修では、不要な複雑性を避け、確実性の高い以下の 3 つの安全対策（アプローチ 1, 2, 3）を導入します：

1. **`touchcancel` ハンドラーの分離**:
   - `touchcancel` イベントリスナーを独立したハンドラー `handleTouchCancel` として登録。
   - `touchcancel` 受信時は Undo / Redo などのいかなるジェスチャーも実行せず、マルチタッチ追跡状態を安全にリセット・破棄する。
2. **ペン直近活動タイムスタンプによるクールダウンガード**:
   - ペン描画中（`pointerdown`, `pointermove`, `pointerup`）に `lastPenTimeRef.current = performance.now()` を常時更新。
   - `handleTouchEnd` で 2本指タップ（Undo）または 3本指タップ（Redo）を判定する際、**ペンが触れていた、またはペン離脱後約 600ms 以内**である場合は、パーム離脱の可能性が高いためタップジェスチャーの発火を完全に抑止する。
3. **ペン接触時のマルチタッチ即時無効化**:
   - スタイラスペンによる `pointerdown` または `pointermove` が発生した瞬間、進行中のマルチタッチ状態を即座に破棄（`activeFingerCount = 0`, `startTime = 0`）し、ペン筆記中の手のひら接触がジェスチャー判定に引き継がれるのを遮断する。

## 3. 期待される効果
- Apple Pencil でサッと素早く文字や記号、短いストロークを描き終えた直後に、手のひらの浮遊によって線が突然消去（Undo）される現象が完全に解消される。
- ユーザーがペンを画面から離して意図的に2本指タップを行った場合には、これまで通りスムーズに Undo が動作する。
