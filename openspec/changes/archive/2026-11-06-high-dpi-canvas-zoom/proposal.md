# Proposal: ズーム拡大時のキャンバス解像度追従とベクター高精細化 (High-DPI Canvas Zoom)

## 1. 課題と背景
StarNote ではピンチ操作やホイール操作により用紙を 50% 〜 400% の範囲で拡大縮小（ズーム）して閲覧・筆記することができます。
しかし、現在のズーム実装は親要素に CSS の `transform: scale(zoomScale)` を適用しているだけであり、`<canvas>` 本体の内部バッファ解像度（`width`, `height` 属性）は等倍表示時（100%ズーム時）の CSS ピクセル × デバイス DPR（Device Pixel Ratio）に固定されています。

このため、200% や 300% に拡大した際、等倍解像度でラスタライズされたビットマップ画像が GPU で単純に引き伸ばされて表示され、手書き線や図形のエッジがぼやけたり、ピクセルがギザギザに荒く見えてしまうという課題が生じています。

StarNote の手書きストロークは、座標・筆圧・太さ・色を保持した純粋なベクター点列データとして保存されています。拡大倍率に応じて Canvas の内部解像度を動的にスケールアップし、ベクターから再描画することで、Retina ディスプレイの物理ピクセル極限まで一切ボケないクッキリとした超高精細な描画体験を実現できます。

## 2. 解決アプローチ
iPad Safari の軽快な描画パフォーマンスとメモリ制約（Canvas メモリ制限）を両立するため、**「操作中の CSS スムーズ変形」と「操作後のダイナミック高解像度レンダリング」を組み合わせたハイブリッド設計**を導入します。

1. **ズーム確定時のダイナミック解像度スケーリング**:
   - `DrawingCanvas` に現在の表示スケール（`zoomScale`）を連携。
   - ピンチ操作が終了（または一定時間静止）したタイミングで、Canvas の物理解像度を `dpr × zoomScale` に動的拡大。
   - `ctx.scale(dpr × zoomScale, dpr × zoomScale)` を適用し、既存のストロークをベクターから再描画。
   - CSS 上の `style.width` / `style.height` は用紙サイズに維持したまま、親の `scale(zoomScale)` と打ち消し合うか、または Canvas 自体の内部解像度を画面上の物理ピクセルと 1:1 に一致させる。

2. **ピンチ操作のスムーズさとパフォーマンス保護**:
   - ピンチ操作中（指を動かしている瞬間）は毎フレームの Canvas リサイズを抑止し、CSS transform による 60fps の滑らかなテクスチャ拡大を維持。
   - ピンチ終了後（指離脱後、またはズーム変化停止後約 150ms のデバウンス）に高解像度キャンバスへ自動切り替え。

3. **iPad Safari のメモリ保護（上限キャップ）**:
   - 無制限な解像度拡大による Safari の Canvas コンテキスト消失（クラッシュ）を防止するため、最大実効解像度（DPR × zoomScale の上限を 4.0 など）または最大キャンバスサイズ制限（4096px）を設定。

## 3. 期待される効果
- 200%〜400% にズームして細かい文字やイラストを描く際も、GoodNotes 同等の一切ボケない美麗で滑らかな手書き線を実現。
- ピンチズーム操作中もカクつくことなく、滑らかな操作感と高画質を両立。
